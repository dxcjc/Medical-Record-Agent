## 本地运行方式

安装依赖后：

```bash
pnpm dev:api
pnpm dev:web
```

常用验证：

```bash
pnpm test
pnpm typecheck
pnpm build
pnpm smoke:production
pnpm eval:manifest evaluation-data/local-deidentified/datasets/lims-clinical-info-local.json
pnpm eval:run
```

注意：

- GitHub Pages 当前只是静态前端站点；完整登录和业务 API 仍依赖单独部署的后端。
- 如果不配置 `VITE_API_BASE_URL`，demo-web 默认 API 地址仍可能指向本地 API。
- 真实脱敏评估样本目录默认不入库，不能提交真实病历原图、未脱敏 OCR 文本、未脱敏 PDF、未脱敏截图、未脱敏导出 JSON 或真实密钥。

## 接手建议

优先级建议如下：

1. **Provider Settings 交互校验**
   - 给 endpoint、model/bucket、timeout、secret ref 增加前端预检。
   - 保存前提示哪些 provider 会被启用、哪些只是草稿。
   - 可先写纯函数测试，例如 `validateProviderConfigDraft`。

2. **Writeback 页面安全反馈**
   - 对空值、阻断原因、只读权限、正在执行状态做更明确的按钮禁用和就近说明。
   - 已有 `WritebackPage.test.ts` 可以继续追加纯函数测试。

3. **Schema Studio 易用性**
   - 增加字段搜索、筛选和当前 schema 变更摘要。
   - 优先避免大改布局，按一个完整内容点提交一次。

4. **视觉回归**
   - 前端改动后尽量用浏览器看 `Dashboard`、`New Recognition`、`Schema Studio`、`Evaluation`、`Writeback`。
   - 确认移动端没有横向滚动，按钮文字不溢出。
