# 领域增强 Prompt 模板 v2

> **设计目标**：将病历结构化抽取的字段级准确率从 62-79% 提升至 85%+。
> **适用 Schema**：medical-record-core v1.1.0（12 字段）、pathology-report-v2（25 字段）
> **对应代码**：`packages/core/src/engine/extractionEngine.ts` → `buildExtractionPrompt()`

---

## 1. 系统角色定义（System Role）

### 1.1 当前版本（v1）

```
你是病历结构化抽取引擎，只输出 JSON，不输出解释性文字。
```

### 1.2 增强版本（v2）

```
你是一名资深肿瘤科病历结构化抽取专家，精通以下领域：
- 肿瘤病理学：熟悉各癌种的组织学分型、免疫组化标志物、分子分型规则
- TNM 分期系统：掌握 AJCC 第 8 版分期标准，理解 pT/pN/m 前缀含义
- 抗肿瘤治疗：了解手术、化疗（方案缩写如 XELOX/mFOLFOX）、放疗、靶向治疗、免疫治疗的规范表述
- 医学 OCR 纠错：能识别 OCR 常见误读（如形近字混淆、数字/字母互换），并根据医学语境修正

你的任务是从 OCR 文本中精准抽取结构化字段。严格遵守以下原则：
1. 只输出 JSON，不输出解释性文字
2. 【不臆造】只抽取文档中明确存在或可直接推断的信息，绝不编造缺失字段的值
3. 【不臆造】当信息缺失或无法确认时，设 value: null，confidence: 0
4. 【不臆造】分期信息不完整时（如只有 T 分期没有 N/M），只输出已有部分，不补造缺失部分
5. 【OCR 修正】对 OCR 文本中明显的医学术语误读，根据上下文自动修正，并在 rawValue 中保留 OCR 原文
```

**设计理由**：
- "肿瘤科病历结构化抽取专家"比"抽取引擎"更能激活模型的医学知识
- 明确列出 4 个专业领域，引导模型优先使用这些知识
- 三条"不臆造"规则分别对应：字段缺失、确认不确定、分期不完整三个高频错误场景
- OCR 修正规则要求 rawValue 保留原文，便于人工审核

## 2. 字段定义模板（Field Definitions）

### 2.1 字段定义格式

每个字段采用以下格式输出：

```
- {key}（{label}，类型：{type}）
  ├─ 提取规则：{如何从 OCR 文本中提取该字段}
  ├─ 正例：{正确的提取场景 → 正确的输出值}
  ├─ 反例：{常见的错误提取场景 → 应该避免的错误}
  └─ 特殊处理：{边界情况的处理方式}
```

### 2.2 各字段完整定义

#### patientName（患者姓名，类型：string）

**提取规则**：
- 从"姓名："、"患者姓名："、"病人姓名："标签后提取
- 同行可能有年龄信息"姓名：张三 年龄：45 岁"，一并获取年龄写在括号内

**正例**：
- 文档写 `姓名：张三` → 输出 `"张三"`
- 文档写 `姓名：王某某 年龄：62 岁` → 输出 `"王某某（62 岁）"`
- 文档写 `患者姓名：李月娥` → 输出 `"李月娥"`

**反例**：
- ❌ 将"送检医生：李四"误认为患者姓名
- ❌ 将医院名称（如"北京协和医院"）误认为患者姓名
- ❌ 将"报告医生：赵肖雅"误认为患者姓名
- ❌ 将"审核医生"、"复诊医生"姓名误认为患者姓名

**特殊处理**：
- 手写体可能识别不准，保留原始 OCR 文本，不要过度修正姓名
- 多文档场景下，以包含"姓名："标签的文档为准

#### tumorType（癌种/肿瘤类型，类型：string）

**提取规则**：
- 从癌种字段、临床诊断或病理诊断中推断
- 优先取病理诊断中的组织学类型，其次取临床诊断

**正例**：
- 文档写 `高级别尿路上皮癌` → 输出 `"膀胱癌"`
- 文档写 `肺腺癌` → 输出 `"肺腺癌"`
- 文档写 `右乳浸润性导管癌` → 输出 `"乳腺癌"`
- 文档写 `非霍奇金淋巴瘤，弥漫性大 B 细胞淋巴瘤` → 输出 `"非霍奇金淋巴瘤"`
- 文档写 `横纹肌肉瘤` → 输出 `"横纹肌肉瘤"`
- 文档写 `胃肠道间质瘤` → 输出 `"胃肠道间质瘤"`
- 文档写 `（距肛缘 15cm 处）中分化腺癌` + 临床诊断 `消化内科` → 输出 `"肠癌"`
- 文档写 `（胰体尾）中分化导管腺癌` → 输出 `"胰腺癌"`
- 文档写 `（胃小弯）中-低分化腺癌` → 输出 `"胃腺癌"`
- 文档写 `弥漫性胶质瘤` → 输出 `"胶质瘤"`
- 文档写 `鳞状细胞癌，分化较差` + 送检材料 `食管` → 输出 `"食管癌"`
- 文档写 `FH 缺陷型肾细胞癌` → 输出 `"肾癌"`

**反例**：
- ❌ 将"送检医生"或"送检科室"等非诊断字段内容误认为肿瘤类型
- ❌ 将基因突变名（如"EGFR L858R"）误认为肿瘤类型
- ❌ 文档只写"肺癌"时自行细化为"非小细胞肺癌"
- ❌ 将免疫组化标志物（如"TTF-1"）误认为肿瘤类型
- ❌ 将"原发灶未明"直接作为肿瘤类型（应如实输出 `"原发灶未明"`）

**特殊处理**：
- 尿路上皮癌 → 膀胱癌（解剖部位映射）
- 间质瘤不是上皮来源的"癌"，不要归入"胃癌"或"肠癌"
- 横纹肌肉瘤是非上皮来源恶性肿瘤，不要误归为"肉瘤癌"
- 病理诊断中有"转移性"前缀时，癌种应取原发部位而非转移部位

#### hospitalName（医院名称，类型：string）

**提取规则**：
- 从文档头部、页眉、"送检单位："、"送检医院："字段提取
- 可能出现多个医院名（送检医院 vs 检测机构），取送检/送检单位的医院

**正例**：
- 文档头部写 `南京医科大学第一附属医院` → 输出 `"南京医科大学第一附属医院"`
- 文档写 `送检单位：成都市第七人民医院` → 输出 `"成都市第七人民医院"`
- 文档写 `送检医院：本院` + 头部有 `吉林省肿瘤医院` → 输出 `"吉林省肿瘤医院"`

**反例**：
- ❌ 将检测公司（如"吉因加"、"燃石医学"）误认为医院名称
- ❌ 将科室名（如"乳腺外科"）误认为医院名称
- ❌ 将"CAP"、"ACCREDITED"等认证标识误认为医院名

**特殊处理**：
- "本院"需结合文档上下文推断实际医院名
- 医院别名应保留全称（如"省人民医院"如果上下文可推断全称则用全称）

---

#### patientGender（性别，类型：enum）

**枚举值**：`male`=男，`female`=女，`unknown`=未填写

**提取规则**：
- 从"性别：□男 ☑女"中判断勾选项
- 可从身份证号倒数第二位推断（奇数=男，偶数=女）

**正例**：
- 文档写 `性别：女` → 输出 `"female"`
- 文档写 `性别：男` → 输出 `"male"`
- 身份证号 `622801194501260210` 倒数第二位 `1`（奇数）→ `"male"`

**反例**：
- ❌ OCR 将"性别：病情汇报"误读时，不应将"病情汇报"解析为性别
- ❌ 无法判断时应设 `unknown`，不要猜

**特殊处理**：
- OCR 难以区分 □ 和 ☑，若无法判断则标记 `unknown` 并保留原文

---

#### sampleType（样本类型，类型：string）

**提取规则**：
- 从"样本类型："、"标本类型："、"送检材料："字段提取
- 可能是多选，用逗号分隔

**正例**：
- 文档写 `样本类型：福尔马林浸泡组织(胃）` → 输出 `"福尔马林浸泡组织"`
- 文档写 `标本类型：荷瘤空肠+侵犯的结肠标本` → 输出 `"荷瘤空肠+侵犯的结肠标本"`
- 文档写 `标本类型：新辅助治疗标本` → 输出 `"新辅助治疗标本"`
- 文档写 `标本类型：活检` → 输出 `"活检"`
- 勾选 `内镜活检☑穿刺活检□手术标本□` → 输出 `"内镜活检"`

**反例**：
- ❌ 将"肿瘤大小"误认为样本类型
- ❌ 将"石蜡切片"和"组织"拆成两个字段

---

#### detectionItems（检测项目，类型：string）

**提取规则**：
- 从基因检测区域提取已勾选或列出的检测项目
- 多项用逗号分隔

**正例**：
- 文档写 `检测项目：人类肺癌多基因联合检测` → 输出 `"人类肺癌多基因联合检测"`
- 勾选 `肿瘤 9 基因☑ 肿瘤 13 基因□ 1021 基因☑` → 输出 `"肿瘤 9 基因,1021 基因"`
- 文档写 `送检项目：肿瘤用药基因检测优创版 plus(组织)` → 输出 `"肿瘤用药基因检测优创版plus(组织)"`

**反例**：
- ❌ 将单个基因突变（如"EGFR"）误认为检测项目（应是"EGFR 单基因检测"之类的完整名称）
- ❌ 将检测方法（如"荧光 PCR 法"）误认为检测项目

---

#### reportDate（报告日期，类型：string）

**提取规则**：
- 从"报告日期："、"诊断日期："、"送检日期："字段提取
- 优先取报告日期，其次取诊断日期

**正例**：
- 文档写 `报告日期：2026-01-27` → 输出 `"2026-01-27"`
- 文档写 `送检日期：2026-04-09` → 输出 `"2026-04-09"`
- 文档写 `报告日期：2025-10-29 16:01:0` → 输出 `"2025-10-29"`

**反例**：
- ❌ 将"出生日期"误认为报告日期
- ❌ 将"样本采集日期"误认为报告日期（除非没有报告日期）
- ❌ 将"样本接收日期"误认为报告日期

**特殊处理**：
- 归一化为 YYYY-MM-DD 格式，去除时间部分
- 手写日期格式不规范时保留原文

---

#### treatmentHistory（治疗史，类型：string）

**提取规则**：
- 从治疗史、手术史、用药史、化疗、放疗等字段提取
- 可能是勾选项或文字叙述，保留原文关键信息

**正例**：
- 勾选 `手术☑化疗☑放疗☑` → 输出 `"手术、化疗、放疗"`
- 文档写 `手术史：胃+上切缘+第 8 组淋巴结切除术` → 输出 `"胃+上切缘+第8组淋巴结切除术"`
- 文档写 `2024-01 至 2024-06，XELOX 方案` → 输出 `"XELOX方案"`
- 文档写 `用药史：无` + `放疗史：无` → 输出 `"无"`
- 文档写 `2025-07，安罗替尼` → 输出 `"安罗替尼"`
- 化疗用药表中多行记录 → 合并为 `"贝伐珠单抗+卡培他滨,奥沙利铂+亚叶酸钙+氟尿嘧啶..."`

**反例**：
- ❌ 将"家族史：无"误认为治疗史
- ❌ 将"既往史：无"误认为治疗史
- ❌ 用药表格中的"年份"、"日期"列头误认为治疗内容

**特殊处理**：
- 用药记录可能跨多页，需合并提取
- "不详"应如实保留，不要替换为"无"

---

#### pathologicalDiagnosis（病理诊断，类型：string）

**提取规则**：
- 从"病理诊断："、"诊断意见："字段提取原文
- 当存在初次诊断和补充诊断时，取补充诊断（更完整、更确定的版本）

**正例**：
- 文档写 `病理诊断：（右肾）恶性肿瘤...符合 FH 缺陷型肾细胞癌` → 完整输出原文
- 初次 `提示上皮源性恶性肿瘤` → 补充 `支持乳腺来源` → 取补充诊断
- 文档写 `（膀胱）高级别尿路上皮癌伴局部鳞状分化` → 完整输出

**反例**：
- ❌ 截断病理诊断只取癌种名，丢失分化程度、侵犯范围等细节
- ❌ 将"肉眼所见"或"镜下所见"混入病理诊断
- ❌ 将免疫组化结果混入病理诊断（应单独处理）

**特殊处理**：
- 病理诊断可能很长，完整保留不要截断
- 多个部位的诊断用分号分隔

---

#### clinicalStage（分期，类型：string）

**提取规则**：
- 从分期字段提取 TNM 分期或总体分期信息
- 可能出现在"病理分期："、"pTNM 分期"、"临床分期："等标签后

**正例**：
- 文档写 `pTNM 分期：pT3NOMx` → 输出 `"pT3N0Mx"`
- 文档写 `病理分期：AJCC(2017 第 8 版) pT3N2Mx` → 输出 `"pT3N2Mx"`
- 文档写 `临床分期：IIa 期` → 输出 `"IIa期"`
- 文档写 `ypT：1cN：1 M：X` → 输出 `"ypT1cN1MX"`
- 只有 `pT:T1b(m）pN:NO` 没有 M → 输出 `"pT1bpN0"`（不补造 M）

**反例**：
- ❌ 文档无分期信息时编造分期
- ❌ 只有 T 分期时自行补造 N0M0
- ❌ 将 Gleason 评分（如"3+3=6 分"）误认为 TNM 分期
- ❌ 将"分子生物学分型：Luminal B"误认为临床分期

**特殊处理**：
- 【不臆造】分期信息不完整时只输出已有部分
- 【不臆造】文档完全没有分期相关内容时设 value: null

---

#### geneMutations（基因突变，类型：string）

**提取规则**：
- 从基因检测结果中提取关键突变信息
- 仅提取明确报告的突变（阳性/检出结果）

**正例**：
- 文档写 `EGFR 基因 Exon-21(L858R) 突变` → 输出 `"EGFR L858R"`
- 文档写 `检出 NTRK3 基因融合阳性` → 输出 `"NTRK3融合阳性"`
- 文档写 `ALK 融合基因...突变` → 输出 `"ALK融合"`

**反例**：
- ❌ 将"野生型"（Wild Type）误认为突变
- ❌ 将"未检出"的基因列为突变结果
- ❌ 将检测项目名称（如"9 基因"）误认为突变结果

**特殊处理**：
- 多个突变用逗号分隔
- 野生型和未检出不列入

---

#### notes（备注，类型：string）

**提取规则**：
- 从备注、特殊说明、免疫组化（IHC）、肿瘤标志物、送检医生、科室等字段提取补充信息
- 仅提取文档中明确写出的内容

**正例**：
- 免疫组化 `CK7(+), TTF-1(+), Ki-67(约 5%)` → 输出在备注中
- 文档写 `送检医师：马斌` → 输出 `"送检医师：马斌"`
- 文档写 `送检科室：骨与软组织肿瘤科门诊` → 输出 `"送检科室：骨与软组织肿瘤科门诊"`

**反例**：
- ❌ 自行总结或概括文档内容
- ❌ 将病理诊断中的详细信息重复写入备注

**特殊处理**：
- 可包含多项信息，用分号分隔
- 免疫组化结果按原文记录，不要解读

## 3. 不臆造约束规则（Anti-Fabrication Rules）

以下约束以 system prompt 形式嵌入，确保模型不会编造缺失信息：

```
【核心约束：不臆造（Anti-Fabrication）】

1. 空值规则：当 OCR 文本中不存在某字段的对应信息时，返回 value: null, rawValue: "", confidence: 0。
   - 不要用"未提及"、"不详"、"无"等文字填充本不存在的字段。
   - 仅当文档明确写出"不详"或"无"时，才可以使用这些值。

2. 分期不补造规则：
   - 如果文档只有 T 分期，不要自行添加 N0M0。
   - 如果文档只有 N 分期，不要自行添加 T 和 M。
   - 如果文档写"ypT:1 cN:1 M:X"，如实输出，不要将 M:X 改为 M0 或 M1。

3. 诊断不升级规则：
   - 文档写"倾向腺癌"不要改为"腺癌"（除非后续有补充诊断确认）。
   - 文档写"考虑...来源"不要改为确定性诊断。
   - 文档写"疑为"、"待排"时保留不确定性表述。

4. 癌种不细化规则：
   - 文档只写"肺癌"不要自行细化为"非小细胞肺癌"或"肺腺癌"。
   - 文档只写"肠癌"不要自行细化为"结直肠癌"或"直肠癌"。
   - 只有当文档明确写出亚型时才可以使用更具体的名称。

5. 基因检测不推断规则：
   - 只报告文档中明确"检出"或"突变"的基因。
   - "野生型"、"未检出"不计入 geneMutations。
   - 不要根据癌种类型推断可能存在的基因突变。

6. 多诊断取最终规则：
   - 当存在初次诊断和补充诊断时，以补充诊断为准。
   - 当存在"倾向..."和确定诊断时，以确定诊断为准。
```

## 4. OCR 纠错提示（OCR Correction Hints）

### 4.1 嵌入 Prompt 的纠错指令

以下内容作为 Prompt 的一部分发送给 LLM，引导其进行 OCR 纠错：

```
【OCR 纠错指南】

OCR 文本中可能存在以下类型的错误，请根据医学语境自动修正：

A. 形近字混淆（高频）：
   - "腺病" → 可能是"腺癌"（根据上下文判断）
   - "肿摇" → "肿瘤"
   - "纳理号" → "病理号"
   - "恶陛" → "恶性"
   - "浸泪性" → "浸润性"

B. 数字/字母互换（高频）：
   - "R0S1" → "ROS1"（数字 0 和字母 O）
   - "Vi1lin" → "Villin"（数字 1 和字母 l）
   - "Glypicar-3" → "Glypican-3"（字母顺序错误）
   - "Bc1-2" → "Bcl-2"（数字 1 和字母 l）
   - "Cyc1inD1" → "CyclinD1"

C. 医学术语常见误读：
   - "mLH1" → "MLH1"
   - "SH2" → "MSH2"（缺失前缀 M）
   - "PS2" → "PMS2"（缺失前缀 PM）
   - "Claudn1B2" → "Claudin1B2"
   - "D0G-1" → "DOG-1"

D. 药物名称常见误读：
   - "贝伐珠丹抗" → "贝伐珠单抗"
   - "贝优珠丹坑" → "贝伐珠单抗"
   - "垦沙利铂" → "奥沙利铂"
   - "实沙利拍" → "奥沙利铂"
   - "氟尿吨啶" → "氟尿嘧啶"
   - "氟尿密啶" → "氟尿嘧啶"
   - "安罗昔尼" → "安罗替尼"
   - "卡培地滨" → "卡培他滨"
   - "卡培他演" → "卡培他滨"
   - "甘氨双坐钠" → "甘氨双唑钠"

E. 纠错原则：
   - 修正时在 rawValue 中保留 OCR 原文，value 中写修正后的值
   - 仅修正有把握的错误，不确定时保留原文
   - 纠错基于医学语境（如在免疫组化区域出现的"mLH1"大概率是"MLH1"）
   - 不要过度纠错——人名、罕见术语保留原文
```

### 4.2 OCR 纠错与现有代码的集成点

当前系统中 OCR 纠错可通过两个路径实现：

1. **Prompt 内嵌**（本文档描述的方式）：在 `buildExtractionPrompt()` 生成的 prompt 中加入纠错指令，让 LLM 自行修正
2. **前置文本替换**（`docs/ocr-correction-dict.json`）：在 OCR 结果送入 LLM 之前，通过字典映射做确定性替换

**建议策略**：两者结合。确定性高的映射用前置替换（如药物名），需要语境判断的错误由 LLM 修正。

## 5. 证据要求（Evidence Requirements）

```
【证据要求】

1. 每个有值字段必须给出 evidence.snippet、evidence.startOffset 和 evidence.endOffset。
   - evidence.snippet 必须是 OCR 原文中的连续片段
   - startOffset/endOffset 基于拼接后的 OCR 全文字符位置
   - 尽量给出 pageNumber 或 blockId

2. 无法判断的字段返回 value: null，rawValue 使用空字符串，confidence 设为 0。

3. 不要输出 schema.fields 之外的字段 key。

4. confidence 评分指南：
   - 0.9-1.0：信息明确、标签清晰、无歧义（如"姓名：张三"）
   - 0.7-0.9：信息较明确但需要少量推断（如从病理诊断推断癌种）
   - 0.5-0.7：信息部分可见或需要较多推断（如手写体、OCR 质量差）
   - 0.0-0.5：信息缺失或高度不确定
```
