## 一、团队分工

### 1.1 角色定义

| 角色 | 负责人 | 职责 |
|------|--------|------|
| **Hermes（调度员）** | 当前Agent | 统一调度、进度跟踪、质量审核、报告生成 |
| **Codex（执行者）** | Codex CLI | 代码实现、构建验证、单元测试 |
| **Claude Code（备用）** | Claude CLI | Codex失败时接管、并行执行独立任务 |

### 1.2 协作规则

1. **调度员不写代码**：Hermes只负责任务分配、进度监控、结果审核
2. **执行者不决策**：Codex/Claude Code只负责实现，不改变需求
3. **审核闭环**：每个任务完成后必须经过Hermes审核才能进入下一阶段
4. **失败升级**：Codex失败3次后自动升级给Claude Code

```bash

cd /tmp/Medical-Record-Agent
git checkout main

# 3. 重新构建
npm run build

# 4. 重启服务
npm run start
```

**配置回滚**：
- 知识库文件：恢复备份的JSON文件
- 数据库配置：恢复Provider配置

## 五、沟通机制

### 5.1 进度汇报

**频率**：每天2次（上午、下午）

**汇报内容**：
- 今日完成任务
- 遇到的问题
- 明日计划

**汇报方式**：
- 调度员（Hermes）生成进度报告
- 发送到飞书群

### 5.2 问题升级

**升级流程**：
1. 执行者（Codex）遇到问题 → 尝试自行解决（3次）
2. 3次失败 → 升级给调度员（Hermes）
3. 调度员分析 → 决定是否升级给备用（Claude Code）
4. 备用接管 → 继续执行

### 5.3 审核机制

**审核节点**：
- 每个任务完成后必须审核
- 审核通过才能进入下一阶段
- 审核不通过必须返工

**审核标准**：
- 代码质量：无语法错误、无明显bug
- 功能完整性：满足验收标准
- 测试通过：单元测试、集成测试
