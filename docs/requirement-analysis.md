## 一、概述

### 1.1 现状

病历识别系统当前对 45 个固定测试样本的识别率约 62%–79%，未达到"良好"标准（字段级准确率 > 90%，完全正确率 > 80%）。系统主要瓶颈分布于 OCR 文本质量、复杂诊断推理、多文件信息聚合、勾选项识别等多个维度。

### 1.2 测试集结构

8 个测试方向，45 个样本（66 个图片文件），覆盖从基础癌种识别到复杂多文件聚合的全链路场景。

| 方向 | 样本数 | 图片数 | 测试重点 |
|------|--------|--------|----------|
| 1. 不同癌种解读匹配 | 10 | 11 | 癌种识别准确性 |
| 2. 不同类型病理报告 | 10 | 11 | 报告格式兼容性 |
| 3. 不同类型图片识别 | 7 | 9 | 图片类型容错 |
| 4. 药厂测试 | 3 | 3 | 药厂申请单识别 |
| 5. 资料多样本测试 | 5 | 22 | 多文件合并识别 |
| 6. 基因检测 | 3 | 3 | 基因检测报告识别 |
| 7. 手术分期 | 4 | 4 | 分期信息提取 |
| 8. 多部位识别 | 3 | 3 | 多部位/多癌种识别 |

## 二、各方向业务场景分析

### 方向 1：不同癌种解读匹配（10 个样本）

#### 业务场景

肿瘤精准治疗的第一步是准确识别癌种。不同癌种对应不同的治疗路径、用药方案和临床试验入组条件。本方向测试系统对 10 种不同癌种的识别能力，覆盖常见癌种和少见癌种。

#### 样本特征分析

| 样本 | 癌种 | 特征 |
|------|------|------|
| 260518101 | 膀胱癌 | 标准病理报告，诊断明确"高级别尿路上皮癌" |
| 260518102 | 肛缘肠癌 | 简单报告，诊断"中分化腺癌"，需从部位推断癌种 |
| 260518103 | 横纹肌肉瘤 | 少见癌种，会诊报告，有原单位和会诊单位双重免疫组化 |
| 260518104 | 非霍奇金淋巴瘤 | 侵袭性 B 细胞淋巴瘤，免疫组化复杂 |
| 260518105 | 肾癌 | FH 缺陷型肾细胞癌，少见亚型 |
| 260518106 | 胶质瘤 | 脑部肿瘤，弥漫性胶质瘤 WHO3 级 |
| 260518107 | 食管癌 | 鳞状细胞癌，多标本（胃窦+食管），需区分主次诊断 |
| 260518108 | 胃肠道间质瘤（GIST） | 非上皮来源肿瘤，需与胃腺癌区分 |
| 260518109 | 胰腺癌 | 新辅助化疗后，分期复杂（ypT1cN1MX） |
| 260518110 | 胃腺癌 | 标准术后病理，AJCC 分期 pT3N2Mx |
| 260518111 | 期望截图 | 胃腺癌的标准识别结果参考 |

#### 验收标准

| 验收项 | 标准 | 判定方式 |
|--------|------|----------|
| 癌种识别 | 输出的肿瘤类型与文件名标注的癌种一致 | 精确匹配或归一化后匹配 |
| 癌种粒度 | 不过度细化（如文件写"肺癌"不自行改为"肺腺癌"），也不过度泛化 | 与原文一致 |
| 少见癌种 | 横纹肌肉瘤、GIST、FH 缺陷型肾细胞癌等少见类型正确识别 | 精确匹配 |
| 原发部位 | 癌种关联的原发部位正确 | 部位-癌种映射一致 |
| 主次诊断 | 多诊断场景（如食管癌样本含胃窦活检）正确区分 | 主诊断匹配 |
| 不臆造 | 文档未明确癌种时不输出臆造结果 | 未提及字段留空 |

### 方向 2：不同类型病理报告（10 个样本）

#### 业务场景

病理报告是肿瘤诊断的金标准，但格式因医院、报告类型（常规/会诊/补充/细胞学）差异极大。本方向测试系统对多种病理报告格式的兼容能力。

#### 样本特征分析

| 样本 | 报告类型 | 特征 |
|------|----------|------|
| 260518201 | 北医三院电子病历 | HIS 系统导出格式，有初始诊断+补充诊断，含免疫组化 |
| 260518202 | 华西医院会诊报告 | 先不确定后确诊，有"再发报告"机制 |
| 260518203 | 大量文本病理报告 | 新辅助治疗后评估，含大量淋巴结评估和治疗反应 |
| 260518204 | 不常见报告格式 | 病情汇报格式（非标准病理报告），含 TNM 分期、分子分型 |
| 260518205 | 局部病理报告 | 以免疫组化+病理诊断为主体的紧凑格式 |
| 260518206 | 南京鼓楼医院 | 乳腺癌改良根治标本，含 Nottingham 评分和 AJCC 分期 |
| 260518207 | 肠癌肝转移 | 穿刺活检报告，原发灶为肠癌，转移灶在肝脏 |
| 260518208 | 乳腺癌肝转移 | 病理补充诊断+分子靶标检测报告，支持乳腺来源判断 |
| 260518209 | 原发灶未明 | 腹水细胞学报告，腺癌，考虑女性生殖系统来源 |
| 260518210 | 隔页资料 | 同一患者的 2 页病理报告（不同内容），需合并识别 |

#### 验收标准

| 验收项 | 标准 | 判定方式 |
|--------|------|----------|
| 病理诊断 | 与文档中病理诊断原文一致 | 文本匹配 |
| 报告类型感知 | 区分常规报告、会诊报告、补充报告、细胞学报告 | 文档类型枚举正确 |
| 初始 vs 补充诊断 | 260518201/260518202 有补充诊断时，正确区分 | 补充诊断字段有值 |
| 信息完整性 | 肉眼所见、免疫组化、分期等关键信息完整提取 | 关键字段非空 |
| 隔页合并 | 260518210 两页信息正确合并为一个病例 | 信息不丢失不重复 |
| 复杂诊断推理 | 转移癌样本（207/208）正确判断原发灶和转移灶 | 原发部位+转移部位正确 |
| 不臆造 | 未提及的字段不输出 | 空值即正确 |

### 方向 3：不同类型图片识别（7 个样本）

#### 业务场景

临床实际上传的图片类型多样，包括标准扫描件、手机拍照、手写申请单、勾选项、基因检测报告截图等。本方向测试系统对不同图片质量和类型的容错能力。

#### 样本特征分析

| 样本 | 图片类型 | 特征 |
|------|----------|------|
| 260518301 | MRD 申请单 | 勾选了治疗史，但需输出"具体不详" |
| 260518302 | 文字描述手术史 | 子宫内膜癌，手术史在文字描述中而非勾选框 |
| 260518303 | 手写申请单 | 宣武医院手写分子检测申请单，OCR 难度最高 |
| 260518305 | 基因检测报告 | 结直肠癌精准诊疗基因检测，从报告中提取诊断 |
| 260518306 | 含用药信息的申请单 | 乳腺癌申请单含用药史 |
| 260518307 | 三图合并 | 同一患者 3 张图片需合并识别 |
| 260519304 | 综合描述 | 一段话中包含转移、用药和放疗信息 |

#### 验收标准

| 验收项 | 标准 | 判定方式 |
|--------|------|----------|
| 手写体识别 | 260518303 手写姓名、病理号等基本可读 | 关键字段有值且大致正确 |
| 勾选项识别 | 260518301 勾选了治疗史时正确输出"具体不详" | 治疗史字段有值 |
| 文字叙述提取 | 260518302 手术史在文字叙述中时能正确提取 | 治疗史字段有值 |
| 诊断提取 | 260518305/260518306 从基因检测报告中提取诊断 | 肿瘤类型正确 |
| 多图合并 | 260518307 三图合并后信息完整 | 信息不丢失 |
| 综合提取 | 260519304 从一段话中提取转移、用药、放疗 | 多字段有值 |

### 方向 4：药厂测试（3 个样本）

#### 业务场景

药厂临床试验中需要识别样本检测申请单。这类申请单与医院病理报告格式差异大，包含项目编号、研究中心信息、方案号等药厂特有字段，且图片质量参差不齐（截图、拍照、倾斜等）。

#### 样本特征分析

| 样本 | 图片质量 | 特征 |
|------|----------|------|
| 260518401 | 模糊截图 | QLS1304-201 项目，药厂申请单，图片模糊 |
| 260518402 | 清晰截图 | HRS-4508-201 项目，标准药厂申请单 |
| 260518403 | 倾斜拍照 | SHR-A1811-1-203 项目，手机拍摄倾斜 |

#### 验收标准

| 验收项 | 标准 | 判定方式 |
|--------|------|----------|
| 基本信息 | 姓名、性别、年龄等基本信息正确 | 精确匹配 |
| 项目信息 | 方案号、项目编号正确提取 | 有专门字段或备注有值 |
| 模糊容错 | 260518401 模糊图片仍能识别主要内容 | 关键字段有值 |
| 倾斜容错 | 260518403 倾斜图片仍能识别主要内容 | 关键字段有值 |
| 临床诊断 | 诊断信息正确提取 | 肿瘤类型正确 |

### 方向 5：资料多样本测试（5 个样本）

#### 业务场景

真实临床场景中，一个患者可能上传多份资料（病理报告、出院记录、用药记录、基因检测报告等），系统需要将多份资料的信息合并为一个完整的病例画像。这是最复杂的场景，涉及跨文档信息归并和冲突处理。

#### 样本特征分析

| 样本 | 图片数 | 资料类型 | 特征 |
|------|--------|----------|------|
| 260518501 李月娥 | 3 | 期望截图+2张用药记录 | 用药记录非常多（跨 2021–2026 年），含手术、化疗、放疗、靶向多种治疗 |
| 260518502 马辉 | 4 | 期望截图+入院记录+出院记录+实验室备注 | 复杂病史，多线治疗，含临床试验 |
| 260518503 浦慧敏 | 4 | 期望截图+细胞学报告+出院记录(2页) | 肺腺癌多线治疗后，含 EGFR 突变、多线治疗 |
| 260518504 张宏建 | 2 | 入院记录+基因检测 | 2 张资料合并 |
| 260518505 张勇 | 9 | 期望截图+入院记录+治疗记录(7页) | 最多样本，7 页治疗记录 |

#### 验收标准

| 验收项 | 标准 | 判定方式 |
|--------|------|----------|
| 患者一致性 | 多图属于同一患者时不混淆 | 患者姓名一致 |
| 诊断归并 | 多份资料中的诊断信息合并为一个完整诊断 | 主诊断匹配期望 |
| 治疗史归并 | 用药、手术、放疗等治疗信息从多份资料中汇总 | 关键治疗节点不遗漏 |
| 时间线 | 多份资料中的时间信息正确归并 | 时间线连贯 |
| 冲突处理 | 不同资料中的冲突信息标记需审核 | needsReview 标记 |
| 期望截图对照 | 识别结果与期望截图中的标准结果一致 | 关键字段匹配 |
| 信息不丢失 | 22 张图片中任何一张的关键信息不被遗漏 | 全字段覆盖 |

### 方向 6：基因检测（3 个样本）

#### 业务场景

基因检测报告是精准治疗的关键依据，包含基因突变位点、检测方法、临床意义等信息。本方向测试系统从基因检测报告中提取关键信息的能力，包括癌种诊断、检测项目和基因突变结果。

#### 样本特征分析

| 样本 | 报告类型 | 特征 |
|------|----------|------|
| 260518601 | 简要基因检测信息 | 文字较少，包含检测项目（实体瘤 188 基因检测）和诊断（EGFR L858R 突变） |
| 260518602 | 门诊病历含基因信息 | 非基因检测报告本身，而是门诊病历中提及 ALK 融合突变和靶向治疗 |
| 260518603 | 标准分子病理报告 | 北京大学人民医院，包含完整的多基因检测结果表格（ALK/ROS1/EGFR/KRAS/BRAF），最终检出 NTRK3 基因融合 |

#### 验收标准

| 验收项 | 标准 | 判定方式 |
|--------|------|----------|
| 癌种识别 | 从基因检测报告或门诊病历中提取正确的癌种 | 肿瘤类型正确 |
| 检测项目 | 提取检测项目（如"188 基因检测"、"肺癌多基因联合检测"） | 检测项目字段有值 |
| 关键突变 | 检出的基因突变（如 EGFR L858R、ALK 融合、NTRK3 融合）正确提取 | 突变信息正确 |
| 野生型处理 | 260518603 中大量"野生型"基因，不应全部列出 | 突变摘要仅列阳性结果 |
| 临床意义 | 基因检测的临床意义（如"检出 NTRK3 基因融合阳性"）能提取 | 摘要合理 |

### 方向 7：手术分期（4 个样本）

#### 业务场景

手术病理分期（pTNM）是制定术后治疗方案的关键依据。本方向测试系统对不同分期场景的处理能力：完整 TNM 分期、仅有 T/N/M 分期、以及无分期信息的情况。

#### 样本特征分析

| 样本 | 分期场景 | 特征 |
|------|----------|------|
| 260518701 | 标准完整分期 | 左肺上叶鳞癌，pT2N1Mx，有完整淋巴结转移详情 |
| 260518702 | 含 pTNM 但无分期标题 | 右半结肠粘液腺癌，pT3N0Mx，文本中有"仅作临床参考"水印干扰 |
| 260518703 | 只有 N 分期 | 右腋窝淋巴结清扫，pN2a，无 T 和 M 分期 |
| 260518704 | 只有 T 分期 | 左上肺结节浸润性腺癌，pT1c，无 N 和 M 分期 |

#### 验收标准

| 验收项 | 标准 | 判定方式 |
|--------|------|----------|
| 完整分期 | 260518701 正确输出 pT2N1Mx | TNM 精确匹配 |
| 含干扰文本分期 | 260518702 在"仅作临床参考"水印干扰下正确输出 pT3N0Mx | TNM 精确匹配 |
| 仅 N 分期 | 260518703 只输出 N 分期（pN2a），不补造 T 和 M | N 分期正确且 T/M 为空 |
| 仅 T 分期 | 260518704 只输出 T 分期（pT1c），不补造 N 和 M | T 分期正确且 N/M 为空 |
| 不补造规则 | 只有部分分期信息时，绝不臆造缺失部分 | 缺失字段留空 |
| 分期完整性标记 | 标记分期信息的完整性（complete/partial/absent） | 枚举正确 |
| 分期来源 | 标记分期来源（病理分期 vs 临床分期） | 来源正确 |

### 方向 8：多部位识别（3 个样本）

#### 业务场景

部分患者存在多部位病变或多原发癌，系统需要正确识别每个部位的诊断信息，区分原发和转移，避免将不同部位的诊断混淆。

#### 样本特征分析

| 样本 | 场景 | 特征 |
|------|------|------|
| 260518801 | 多部位结肠直肠小肠 | 同一手术标本含直肠、横结肠、小肠多个部位，有腹壁结节和精囊腺累及 |
| 260518802 | 不同部位乳腺癌 | 右侧乳腺癌，穿刺 1 和穿刺 2 显示不同类型（导管原位癌 vs 浸润性癌） |
| 260518803 | 不同部位神经内分泌癌 | 左上叶开口和左下叶开口均为小细胞神经内分泌癌 |

#### 验收标准

| 验收项 | 标准 | 判定方式 |
|--------|------|----------|
| 多部位列举 | 260518801 正确列出直肠、横结肠、小肠等多个部位 | 涉及部位完整 |
| 癌种一致 | 260518803 两个部位均为小细胞神经内分泌癌时统一识别 | 癌种正确 |
| 分级区分 | 260518802 区分导管原位癌和浸润性癌 | 诊断分型正确 |
| 转移 vs 原发 | 260518801 区分原发灶和转移灶（腹壁结节、精囊腺累及） | 原发/转移标记正确 |
| 病理分期 | 多部位场景下分期正确 | pTNM 匹配 |
| 免疫组化 | 多部位样本的免疫组化信息完整提取 | 关键标记物有值 |

## 三、综合验收标准

### 3.1 字段级指标

| 指标 | 目标值 | 计算方式 |
|------|--------|----------|
| 癌种识别准确率 | ≥ 95% | 正确癌种数 / 总样本数 |
| 病理诊断准确率 | ≥ 90% | 病理诊断与原文一致的样本数 / 总样本数 |
| 分期准确率 | ≥ 85% | 分期信息正确的样本数 / 有分期信息的样本数 |
| 治疗史提取率 | ≥ 80% | 治疗史关键信息正确的样本数 / 有治疗史的样本数 |
| 不臆造准确率 | ≥ 95% | 未提及字段正确留空的字段数 / 应留空字段总数 |

### 3.2 样本级指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 完全正确率 | ≥ 80% | 所有字段均正确的样本占比 |
| 需审核召回率 | ≥ 90% | 应标记需审核的样本被正确标记的比率 |
| 幻觉率 | ≤ 5% | 臆造字段的样本占比 |

### 3.3 分方向目标

| 方向 | 当前预估 | 目标值 | 差距 |
|------|----------|--------|------|
| 1. 癌种匹配 | ~75% | 95% | ↑20% |
| 2. 病理报告 | ~65% | 85% | ↑20% |
| 3. 图片类型 | ~60% | 80% | ↑20% |
| 4. 药厂申请单 | ~55% | 75% | ↑20% |
| 5. 多文件合并 | ~50% | 75% | ↑25% |
| 6. 基因检测 | ~70% | 85% | ↑15% |
| 7. 手术分期 | ~60% | 85% | ↑25% |
| 8. 多部位识别 | ~65% | 80% | ↑15% |

## 四、优化方向建议

### 4.1 OCR 层优化（基础设施层）

#### 方案 A：OCR 引擎升级

**问题：** 当前 PaddleOCR 对手写体、倾斜图片、模糊图片识别能力有限。

**建议：**
- 引入多引擎融合策略（PaddleOCR + 百度 OCR API + 腾讯 OCR API），取投票最优结果
- 对手写体场景使用专门的手写 OCR 模型
- 图片预处理增强：自动矫正倾斜、增强对比度、去噪
- 优先级：**P1**

#### 方案 B：图片质量预检与分级

**问题：** 模糊、倾斜等低质量图片直接进入识别流程导致错误率上升。

**建议：**
- 上传时自动评估图片质量（清晰度、倾斜角度、对比度）
- 低质量图片标记警告，提示用户重新上传
- 不同质量等级使用不同的识别策略
- 优先级：**P1**

#### 方案 C：OCR 文本后处理

**问题：** OCR 输出的文本有断裂、错字、顺序错乱等问题。

**建议：**
- 医学术语纠错词典（如"贝伐珠丹抗"→"贝伐珠单抗"、"奥沙利拍"→"奥沙利铂"）
- 文本段落重组（根据语义而非物理位置排序）
- 专有名词标准化（医院名、药品名、基因名）
- 优先级：**P0**

---

### 4.2 Prompt / 模型层优化（推理层）

#### 方案 D：领域增强 Prompt

**问题：** 当前 Prompt 缺乏肿瘤学领域知识，导致诊断推理能力不足。

**建议：**
- 在 System Prompt 中嵌入肿瘤学知识（癌种分类、TNM 分期规则、免疫组化解读指南）
- 添加"不要臆造"的强约束指令
- 分期字段增加规则："如果文档中只有 T 分期，不要补造 N 和 M"
- 针对不同文档类型使用不同的 Prompt 策略
- 优先级：**P0**

#### 方案 E：多轮推理（Chain-of-Thought）

**问题：** 复杂场景（转移癌、多部位、原发灶未明）需要多步推理，单轮抽取易出错。

**建议：**
- 第一轮：OCR 文本预处理 + 文档类型分类
- 第二轮：基础信息提取（患者信息、医院信息、诊断原文）
- 第三轮：高级推理（原发 vs 转移、分期推断、癌种归一化）
- 第四轮：自检（检查是否有臆造、是否符合医学逻辑）
- 优先级：**P1**

#### 方案 F：视觉 LLM 直接识别（绕过 OCR）

**问题：** OCR + LLM 两步流程存在信息损失。

**建议：**
- 对手写体、勾选项等 OCR 难以处理的场景，直接使用视觉 LLM（如 Claude Vision、GPT-4V）
- 视觉 LLM 直接读图提取结构化信息，跳过 OCR 中间步骤
- 可作为 OCR 方案的 fallback 或并行方案
- 优先级：**P1**

---

### 4.3 Schema / 后处理层优化（输出层）

#### 方案 G：癌种知识库映射

**问题：** 病理诊断中的癌种表述多样，需要归一化。

**建议：**
- 建立癌种映射表：原始诊断 → 标准癌种类型
- 支持层级映射："浸润性导管癌" → "乳腺癌" → "恶性肿瘤"
- 少见癌种补充词条（如 GIST、横纹肌肉瘤、FH 缺陷型肾细胞癌）
- 优先级：**P0**

#### 方案 H：分期提取规则引擎

**问题：** TNM 分期格式多样，且存在只出现 T/N/M 之一的情况。

**建议：**
- 正则表达式 + LLM 双重提取：正则捕获标准格式（pT2N1Mx），LLM 处理非标准格式
- 不补造规则硬编码：只有 T 时输出 `tStage` 有值、`nStage`/`mStage` 为 null
- 分期来源标记：区分病理分期（pT）和临床分期（cT）
- 优先级：**P0**

#### 方案 I：多文件合并策略

**问题：** 多图片/多文件场景信息分散，合并困难。

**建议：**
- 多文件 OCR 文本预合并，按时间或内容语义排序
- 同一字段多处出现时，取最新/最权威的值（如补充诊断优先于初始诊断）
- 冲突检测：同一字段不同值时标记 needsReview
- 优先级：**P1**

#### 方案 J：治疗史结构化

**问题：** 治疗史信息来源多样（勾选框、文字叙述、用药记录表格），提取困难。

**建议：**
- 分类提取：手术史、化疗方案（含药物名和剂量）、放疗方案、靶向治疗、免疫治疗
- 时间线归并：从多份资料中提取治疗时间线
- 药物名称标准化（如"贝伐珠丹抗"统一为"贝伐珠单抗"）
- 优先级：**P1**

---

### 4.4 评估与迭代层优化

#### 方案 K：自动化回归评估

**问题：** 缺乏自动化评估流程，无法量化优化效果。

**建议：**
- 建立 ground truth 标注数据集（基于 45 个样本）
- 实现自动评估脚本（字段级精确匹配 + 模糊匹配）
- 每次优化后自动运行回归评估
- 建立评估指标看板（按方向、按字段维度）
- 优先级：**P0**

#### 方案 L：错误分析驱动迭代

**问题：** 当前缺乏系统化的错误分类和分析。

**建议：**
- 建立错误分类体系：OCR 错误、推理错误、臆造错误、遗漏错误、格式错误
- 对每个错误标注根因和修复方向
- 按错误频率排序优先修复
- 优先级：**P1**

## 七、风险与建议

### 7.1 关键风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 手写体 OCR 短期内无法突破 | 方向 3 识别率上不去 | 视觉 LLM 直接读图绕过 OCR |
| 少见癌种缺乏训练数据 | 方向 1 的边缘癌种误判 | 知识库补充 + Few-shot Prompt |
| 多文件合并逻辑复杂 | 方向 5 成为最大瓶颈 | 分步实现，先单文档后多文档 |
| 医学术语 OCR 错误 | 影响所有方向 | 术语纠错词典 + 持续维护 |

### 7.2 建议

1. **先做 P0，快速见效**：Prompt 优化 + 知识库 + 分期规则可以在 1 周内完成，预计带来 15–20% 的识别率提升
2. **建立评估基线**：在开始优化前，先对 45 个样本做一次完整评估，建立精确的基线数据
3. **分方向独立评估**：不同方向的瓶颈不同，需要分别跟踪优化效果
4. **用户参与验证**：优化后的结果需要业务人员（病理科医生、检验科技术人员）验证

### 8.2 现有 Schema 对照

当前系统有两套 Schema：
- `schema-medical-record-core.json`：19 个字段，通用病历
- `schema-pathology-report-v2.json`：24 个字段，病理报告专用

**差距分析：**
- 缺少药厂申请单专用字段（方案号、项目编号、研究中心）
- 缺少基因检测结果结构化字段（检测项目、突变位点、检测方法）
- 治疗史仅为单个 string 字段，不足以承载多线治疗的结构化信息
- 分期字段未区分 T/N/M 独立提取（core schema 只有 staging 一个字段）

建议基于本报告的分析结果，升级 Schema 以覆盖所有 8 个测试方向的需求。
