# 肿瘤基因检测申请单识别 — 产品需求升级方案

> **版本：** v1.0  
> **日期：** 2026-06-13  
> **作者：** AI 产品经理  
> **状态：** 待用户确认

---

## 一、背景与目标

### 1.1 当前能力
- ✅ OCR 提取印刷体文字
- ✅ LLM 视觉增强（识别勾选框、手写体）
- ✅ 结构化字段抽取（26 个字段）
- ✅ 置信度评分和证据链

### 1.2 问题
- ❌ 任务详情页只显示扁平字段列表，没有按业务逻辑分组
- ❌ 勾选项（如检测项目）显示为 JSON 数组，不直观
- ❌ 没有"看图对照"功能，复核人员无法对比原图和抽取结果
- ❌ 没有批量处理能力，一次只能识别一份
- ❌ 没有与 LIMS 系统对接的标准化输出

### 1.3 目标
**让医院病理科/检验科工作人员能快速、准确地完成肿瘤基因检测申请单的数字化录入。**

---

## 二、用户场景

### 2.1 核心用户
- **病理科医生**：需要把纸质申请单录入 LIMS 系统
- **检验科技术人员**：需要核对检测项目和样本信息
- **质量管理员**：需要审核识别结果的准确性

### 2.2 使用流程
```
纸质申请单 → 拍照/扫描 → 上传系统 → 自动识别 → 人工复核 → 确认写入 LIMS
```

## 三、功能需求

### P0：任务详情页重构（核心）

**目标：** 让复核人员能快速理解和修正识别结果

#### 3.1 字段分组展示
按业务逻辑分为 6 个卡片：

| 分组 | 字段 | 展示方式 |
|------|------|----------|
| **患者信息** | 姓名、性别、年龄、门诊号、电话、身份证号、民族 | Descriptions 表格 |
| **送检信息** | 送检医生、送检日期、病理号、样本编号、诊室 | Descriptions 表格 |
| **临床诊断** | 肿瘤类型、肿瘤分类 | 高亮卡片 + Tag |
| **样本信息** | 标本类型、血液样本、制备时间、肿瘤细胞含量 | Descriptions 表格 |
| **检测项目** | 肺癌项目、消化道项目、其他项目 | **勾选矩阵**（核心） |
| **检测产品** | 检测公司、文件编号、版本 | Descriptions 表格 |

#### 3.2 勾选矩阵组件（核心创新）
```
┌─────────────────────────────────────────────────┐
│ 肺癌检测项目                                      │
├─────────────────────────────────────────────────┤
│ ☑ 肿瘤9基因    ☐ 肿瘤13基因   ☑ 肺癌11基因      │
│ ☑ EGFR         ☐ 肿瘤40基因   ☐ 188基因         │
│ ☑ 1021基因     ☐ 肿瘤mrd(血液) ☐ 实体瘤40基因   │
├─────────────────────────────────────────────────┤
│ 置信度: 88%  │  来源: 第2页左下角  │  [修改]     │
└─────────────────────────────────────────────────┘
```

- 已勾选项高亮显示（蓝色背景）
- 未勾选项灰色显示
- 支持点击切换勾选状态
- 显示置信度和来源位置

#### 3.3 图片对照视图
- 左侧：原图（可缩放、拖拽）
- 右侧：识别结果
- 点击字段时，原图自动定位到对应区域（如果有坐标信息）
- 支持在原图上框选区域重新识别

### P1：批量处理

#### 3.4 批量上传
- 支持一次上传多张图片（同一份申请单的多页）
- 自动合并为一个任务
- 支持拖拽上传

#### 3.5 批量识别队列
- 显示处理进度（排队中、识别中、待复核、已完成）
- 支持优先级调整
- 支持取消任务

### P2：质量管控

#### 3.6 置信度仪表盘
- 整体置信度分布（高/中/低）
- 低置信度字段高亮提醒
- 历史识别准确率统计

#### 3.7 审计日志
- 记录每次修改（谁、什么时间、改了什么）
- 支持回滚到历史版本
- 导出审计报告

### P3：LIMS 对接

#### 3.8 标准化输出
- 导出 HL7 FHIR 格式
- 导出 JSON/CSV
- 自定义字段映射

#### 3.9 自动写回
- 配置 LIMS 系统 API
- 自动写入识别结果
- 失败重试机制

## 七、风险与依赖

### 7.1 风险
- **OCR 质量**：手写体识别率低 → 已通过 LLM 视觉增强缓解
- **LLM 成本**：视觉 API 调用费用较高 → 可配置为可选功能
- **隐私合规**：患者信息脱敏 → 已实现 deidentification 模块

### 7.2 依赖
- PaddleOCR 服务稳定运行
- LLM API 可用且支持视觉
- 前端 Arco Design 组件库
